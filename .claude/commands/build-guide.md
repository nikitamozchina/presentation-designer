---
description: Собрать гайдлайн оформления из папки, которую пользователь указал в «Дизайнере презентаций»
---

Собери гайдлайн по заявке из приложения. `APP` — папка приложения: путь из скилла /presentations, а внутри неё — текущая папка. Всё состояние меняй только через `python3 APP/app/tools/agent.py`, JSON задачи руками не правь.

## 0. Взять задачу
`python3 APP/app/tools/agent.py task-claim guide` → поле `task`.
- `task: null` значит, заявок нет. Скажи пользователю, что сначала нужно нажать «Добавить гайдлайн» в приложении, и остановись.
- `resumed: true` значит, задача уже начиналась. Прочитай `interview_so_far` и `lifecycle` (stage, question) и продолжи с того места. Если `lifecycle.state` = `waiting_user`, повтори пользователю последний вопрос.
- Дальше: `D` = `task.dir` (папка гайда), `NAME` = `task.name`, флаг эталонов — `task.request.options.examples`.

Во время работы перед каждым крупным шагом вызывай `agent.py heartbeat guide "NAME" "<что делаю>"`.

## 1. Изучить исходники (бюджет контекста!)
1. Выполни `python3 APP/app/tools/extract.py "D/Исходники" "D/_extracted" --sheets`. Затем `agent.py task-state guide "NAME" working --stage analysis "Изучаю исходники"`.
2. Прочитай `D/_extracted/index.md`.
3. Дальше читай только нужное:
   - `.md` каждой презентации — там размер слайда, частые цвета, частые кегли, шрифты, макеты и тексты;
   - все контактные листы (`*-листы/лист-*.png`, `картинки-*/сетка-*.png`);
   - отдельные картинки слайдов (`*-slides/NNN.png`) — не больше 12 штук и только когда нужна деталь;
   - PDF-гайды (брендбуки) — частями не больше 20 страниц за раз и не больше 60 страниц всего; сначала оглавление.
   - Никогда не открывай папку картинок поштучно и не читай PDF презентации целиком.
4. Цвета темы pptx часто не совпадают с брендом. Бренд определяй по частым цветам и по тому, что видно на слайдах. Почти-дубли вроде `#0077FF` / `#0E7FFF` / `#0177FF` — это один цвет.
5. Шрифты сопоставляй по разделу «Шрифты» в index.md (семейство + начертание из файла) и по частоте в pptx. «X DemiBold» как имя семейства в pptx — это семейство X с весом 600.

## 2. Чего не хватает — спросить
Если чего-то критичного нет (шрифт используется, а файлов шрифта нет; непонятен главный цвет; нет логотипа):
- Спрашивай по одному вопросу и сразу предлагай варианты. Пример: «Нет файлов шрифта X. Варианты: 1) пришли файлы (положу в гайд); 2) возьму ближайший из Google Fonts — Y; 3) системный шрифт Z».
- Перед вопросом: `agent.py task-log guide "NAME" agent "<вопрос>"` и `agent.py task-state guide "NAME" waiting_user --stage analysis --question "<вопрос коротко>" "Ждёт ответа в чате"`.
- После ответа: `agent.py task-log guide "NAME" user "<ответ>"`, затем `task-state … working`.
- Мелочи не спрашивай: прими разумное решение и запиши его в guide.md, раздел «Допущения».

## 3. Собрать гайдлайн в `D`
`agent.py task-state guide "NAME" working --stage building "Собираю гайдлайн"`.

Файлы копируй командой `agent.py copy guide "NAME" "<откуда внутри D>" "<куда внутри D>"`, например `copy guide "NAME" "Исходники/Brand Sans/Brand Sans Medium.otf" "fonts/Brand Sans Medium.otf"`.

Обязательная структура:
- `fonts/` — файлы шрифтов (otf/ttf/woff2).
- `assets/` — **всё, что может пригодиться слайдам, даже если весит много**: гайд должен быть универсальной библиотекой. Подпапки:
  - `assets/bg/` — фоны (из картинок макетов: `media.md`, колонка «Макеты»);
  - `assets/logo/` — логотипы для светлого и тёмного фона;
  - `assets/icons/`, `assets/icons-*/` — все наборы иконок целиком;
  - `assets/img/` — все 3D, маскоты, иллюстрации;
  - `assets/library/<имя-презентации>/` — **все** картинки из каждой pptx: целиком папка `_extracted/…-медиа` вместе с `по-слайдам.md` и `media.md` (по ним потом ищут по смыслу).
  В проекты копируются только используемые файлы, поэтому размер гайда не мешает.
  После копирования библиотеки выполни `agent.py dedupe guide "NAME"` — дубли из `_extracted` уйдут в Корзину.
- `styles.css` — база для каждого слайда:
  - `@font-face` с `url("fonts/…")`, картинки через `url("assets/…")` (пути от корня гайда — при создании проекта они переносятся автоматически);
  - `:root` с цветами;
  - `.slide { width:1920px; height:1080px; position:relative; overflow:hidden }` и варианты фона (`.slide.blue` и т.п.);
  - типографика классами (`.h` заголовок, `.lead`, `.body`, `.small`, `.num` …);
  - компоненты (карточки, плашки, списки, иконка в кружке, логотип);
  - **таблицы и графики — обязательно, с этими именами классов** (на них опирается создание презентаций): `table.data` (+`.l`, `.total`, `tr.hl`, `tr.sum`), `table.agenda`, `.bars > .bar-col (.v .bar .x)` (+`.key`, `.bar.dim`), `svg.chart` (`.grid .area .line .dot .lbl .val`, `.track .seg .s2 .s3 .s4`), `.legend > .legend-item .sw`, `.delta.up/.down`, `.gantt (.l) > .gantt-head + .gantt-row (.name .track-line .gbar)`. Цвета, шрифты и скругления — по гайду; смотри, как в исходниках оформлены таблицы и графики (найди их по `.md` презентаций и контактным листам).
  - Без внешних URL и `@import`.
- `guide.json` (JSON):
  - обязательно: `id` = NAME, `name`, `version` = 1, `base_css` = "styles.css";
  - желательно: `canvas`, `colors` (hex + где применять), `fonts`, `type_scale_px`, `min_font_px`, `backgrounds`, `components` (имя класса → когда использовать), `layouts` (рецепты слайдов), `assets` (каталог: файл → назначение), `typography_rules`, `layout_rules`, `sources` (что изучено).
- `guide.md` — правила словами для агента, который будет делать презентации:
  - рецепты слайдов: титул, раздел, текст, текст + картинка, сравнение 2–3 колонок, цифры и факты, список шагов, цитата, итоги, спасибо — с классами и координатами;
  - раздел `## Таблицы` — когда таблица, сколько строк/колонок, выравнивание, выделение итога и строки, единицы;
  - раздел `## Графики` — выбор типа (столбцы/линия/кольцо/Ганта), формулы высот и координат, подписи, цвета, «нет данных — нет графика»;
  - раздел про библиотеку: какие наборы есть и на каких слайдах `по-слайдам.md` их искать;
  - что можно и чего нельзя;
  - «Допущения» — что решено без пользователя.
- `examples/` — только если `options.examples` = true. Сделай 10 эталонных слайдов: `01-title.html`, `02-section.html`, `03-text.html`, `04-comparison.html`, `05-numbers.html`, `06-chart-bars.html`, `07-chart-line.html`, `08-chart-donut.html`, `09-table.html`, `10-timeline.html`. Формат каждого:
  `<!doctype html><html lang="ru"><head><meta charset="utf-8"><title>01 Титул</title><link rel="stylesheet" href="../styles.css"></head><body><div class="slide …">…</div></body></html>`.
  Картинки — `../assets/…`. Никаких `<script>` и внешних URL. Текст реалистичный, не «Lorem ipsum».

## 4. Проверить
1. Есть эталоны: `python3 APP/app/tools/check_slides.py --guide "NAME"`. Прочитай `report.md` и контактный лист из ответа. Исправь найденное и запусти проверку снова — до 3 кругов. Посмотри на лист глазами: похоже ли на исходные слайды?
2. `agent.py task-state guide "NAME" ready "Гайдлайн готов"`. Если команда вернёт ошибку со списком недостающего — допиши недостающее и повтори.

## 5. Отчёт в чате
Коротко:
- что взято: цвета, шрифты, сколько ассетов;
- какие допущения сделаны;
- что посмотреть в приложении (клик по гайду в сайдбаре показывает эталоны).

Если на любом шаге работать дальше невозможно: `task-state guide "NAME" failed "<причина простыми словами>"` и объясни пользователю, что сделать.
