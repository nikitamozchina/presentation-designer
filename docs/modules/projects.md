# Новый проект

## Форма (`#projectScrim`, `POST /api/projects`)
| Поле | Обязательно | В request.json |
|---|---|---|
| Задача: Создать / Дополнить / Пересобрать | да | `mode`: create, extend, rebuild |
| Исходная презентация: проект из приложения или файл (только extend/rebuild) | да | `base {type, project?, as}`; файлы — в `Исходники/Основа…` |
| Гайдлайн (только ready) | да | `guide` |
| Тема | да | `topic`, она же имя проекта «Тема — ГГГГ-ММ-ДД» |
| Длительность, мин (1–600; 1 слайд ≈ 1 мин, не жёстко) | нет | `duration` |
| Автор: имя и должность (только для титула) | нет | `author` или null |
| Материалы (файлы и папки) | нет | `references[]` — имена в `Исходники/` |
| «Проверить слайды» (по умолчанию вкл.) | — | `options.self_check` |

- Файлы выбираются родным окном macOS: `POST /api/pick` возвращает токен, пути остаются на сервере. Из одного выбора можно убрать отдельные файлы: `references: [{token, items: [индексы]}]`.
- Проект-основа копируется только частями `slides, styles.css, assets, project.json`. Проект, который ещё собирается, основой быть не может.
- Пресеты автора хранятся в `~/.config/presentation-designer/presets.json` (до 20 штук; путь меняет `PD_CONFIG`). API: `GET /api/presets`, `POST /api/presets {action: save|delete, name, position}`.
- Выпадающие списки сделаны своим компонентом `makeSelect` в app.js, с клавиатурой: ↑↓, Enter, Esc.

## Процедура агента (`.claude/commands/create-presentation.md`)
```
task-claim → изучить гайд (guide.md, guide.json, examples/*, лист эталонов)
           → extract.py исходников → интервью (≤10 вопросов, по одному)
           → brief/brief.md → структура в чате → «ок»
           → init-project → слайды slides/NN-slug.html (sync-slides каждые 2–3)
           → [self_check] check_slides.py + чек-лист «глазами», до 3 кругов
           → task-state ready → отчёт в чате
```
- Каждый вопрос и ответ записывается в `task-log`. Перед вопросом ставится `waiting_user` с `--question`. Структура попадает в журнал полностью.
- Цифры и факты берутся только из исходников и ответов. Нет данных — нет графика: вместо него слайд словами или видимая пометка `[нужны данные: …]`.
- Разметка слайдов как у эталонов гайда. Цвет текста задаётся только классами гайда, серый `--muted` — только на белом. Блоки заполняют область контента.
- Автор появляется только на титуле и только если задан.
- Режимы:
  - **extend + проект** — слайды основы копируются (`agent.py copy`), новые вставляются между ними;
  - **extend/rebuild + файл** — файл служит только источником текста и картинок, все слайды делаются заново;
  - **rebuild + проект** — содержание основы переносится в новый гайд.

## Ассеты (`agent.py init-project`, `sync-slides`, `sync-assets`)
- `init-project` копирует в проект `styles.css` гайда, переписывая `url(fonts/…)` в `url(assets/fonts/…)`. Также копирует `fonts/` в `assets/fonts/` и только `assets/bg`, `assets/logo`.
- Слайд ссылается на любую картинку гайда как `../assets/<путь в гайде>`. `sync-slides` и `sync-assets` докопируют только реально используемые файлы, поэтому библиотека гайда в сотни МБ в проект не попадает. Если файла нет и в гайде — `ok: false` со списком.
- `sync-slides` обновляет `project.json` по папке `slides/` (под `update_project`): `<title>` слайда становится его названием, NN — порядком.
