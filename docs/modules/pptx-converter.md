# Экспорт в PPTX (итерация 4, 2026-10-13)

Решения автора:
- файл редактируемый;
- без pip у пользователей;
- файл строится с нуля, без шаблона;
- SVG-графики — картинкой;
- рядом с файлом папка «Шрифты»;
- скрытые слайды не включаются;
- качество проверяется в dev-тестах.

## Как устроено
```
 visible slides ─► GET /pptx-scan/<p>      Chrome --dump-dom: SCAN_JS обходит слайды в sandbox-iframe
                    │                      → JSON: тексты (runs), блоки, картинки, растр, @font-face
                    └► GET /pptx-raster/<p>/<id>  тот же обход помечает растровые элементы, прячет остальное,
                                           фон прозрачный → Chrome --screenshot 2× (--virtual-time-budget)
 app/core/pptx_export.py ─► JSON → объекты слайда (шрифты, градиенты, обрезка)
 app/core/pptx.py        ─► OOXML на stdlib (zip + XML по ECMA-376), атомарная запись, chmod 644
```
- Модули: `core/pptx.py` (писатель), `core/pptx_export.py` (COMMON_JS/SCAN_JS/RASTER_JS + перевод), `core/exporter.py::_export_pptx`.
- Растровые вставки — один PNG слоя на слайд, обрезанный `a:srcRect`. Слой снимается только для слайдов, где есть растр.
- Стадии в статусе: `scan` → `raster` (N из M) → `build`; `raster` = номера слайдов с нередактируемыми элементами.

## Что переносится объектами
| HTML | PPTX |
|---|---|
| Текст (элемент с прямым текстом; `::before/::after` с текстом — ▲▼) | текстбокс, runs: шрифт, кегль px/2, цвет с альфой, bold/italic, подчёркивание, зачёркивание, `letter-spacing` → `spc`, uppercase → текст заглавными, `lang` по тексту |
| Блок с фоном, рамкой, градиентом | rect / roundRect / ellipse; `round2SameRect` (+flipV) для скругления только сверху или снизу (столбцы) |
| Частичные рамки (таблицы, разделители) | тонкие прямоугольники |
| Абсолютные `::before/::after` с фоном (маркеры, затемнение фото) | фигуры |
| `<img>` png/jpeg/gif из проекта | картинка; `object-fit` contain/cover/scale-down; рамка картинки — кольцом-фигурой; обрезка по предку с `overflow:hidden` (и скругление, если фото на всю карточку) |
| Фон слайда: цвет, linear-gradient, картинка cover | фигура / картинка на весь слайд |

## Что уходит картинкой (растр) — `rasterReason()` в COMMON_JS
svg, canvas, video, iframe, `.ad` (баннеры), картинки не из проекта или не png/jpeg/gif, `filter`, `transform`, `box-shadow`, `text-shadow`, `clip-path`, `mask`, `mix-blend-mode`, `backdrop-filter`, radial/conic/повторяющиеся и многослойные фоны, разные скругления углов (кроме «два верхних / два нижних»).
- Растр снимается всем поддеревом. Рамка растра — объединение рамок потомков (подписи svg за краем) + запас, с клампом по слайду.
- В отчёт «нередактируемо» (статус `raster`, сообщение в окне экспорта) попадают только растровые элементы с текстом и графики. Логотипы и иконки — картинки и так.

## Шрифты
- Сканер собирает `@font-face`, которые документ реально объявил.
- Run сопоставляется по алгоритму CSS font matching (`match_face`), затем файл, затем имя для Office: **nameID 1** (legacy family) + bold по fsSelection bit 5, italic по bit 0 (`font_info`).
  - Пример: 400 → «Brand Sans»; 500 → «Brand Sans Medium»; 600 → «Brand Sans DemiBold»; 700 → «Brand Sans» + b (у каждого начертания свой nameID 1, кроме Regular/Bold).
  - 300 без своего `@font-face` → Regular, как в браузере.
- Нет файла (системный шрифт, woff2) → имя из CSS.
- В «Шрифты/» копируются только реально использованные файлы.

## Калибровка (по PowerPoint для Mac)
- Ширина текстбокса = ширина в браузере × 1,025 + 4 px (`PD_PPTX_SLACK`).
  - Подобрано замером строк:
    | Запас | Демо | Эталоны |
    |---|---|---|
    | 0 + 2 px | 90% | ломаются заголовки |
    | 2–3% | 98,2–98,5% | 100% |
    | 6% + 6 px (прототип) | 97,9% | 100% |
  - С большим запасом в строку влезает больше слов, чем в браузере.
- Плотный межстрочный (< 1,2 кегля): текстбокс опускается на (1,2·fs − lh)·0,95 — из прототипа.
- Поля 0, без автоподбора; однострочный — без переноса.

## Проверки качества (dev)
- `app/tests/test_pptx.py` (9):
  - структура пакета: content types, rels, id;
  - единицы, градиент 1 стоп → заливка, клампы, суррогаты;
  - атомарность при сбое, права 644;
  - шрифты на реальных OTF и CSS matching;
  - углы градиентов, object-fit, обрезка.
- `app/tests/ui/pptx_xsd.py` — каждая XML-часть по XSD ECMA-376 Transitional. Ловит порядок элементов и диапазоны: проверено подсунутыми ошибками.
- `app/tests/ui/pptx_compare.py` — экспорт → PowerPoint (AppleScript, файл в sandbox-контейнере) → PDF → PNG.
  - Порог: число строк совпало у ≥95% текстовых блоков и у 100% заголовков; нет потерянных текстов; растровые вставки совпадают по пикселям.
  - Отчёт + листы «HTML | PowerPoint» с рамками расхождений.
- Результат 2026-10-13:
  | Проект | Совпадение строк |
  |---|---|
  | Эталоны (10 слайдов) | 100% (127/127) |
  | Демо (29 слайдов) | 98,2% (320/326) — остаток: шум измерителя |
  | Эталоны на Arial | 100% |

  XSD: все части валидны. Первую версию (до правок по ревью) открыли вручную в PowerPoint — без «восстановить»; итоговую открывает PowerPoint через AppleScript в `pptx_compare` без ошибок.
- Против прототипа (тот же путь через PowerPoint, демо): наш файл ближе к HTML на 23 слайдах из 28, прототип — на 5. Это 4 слайда с баннерами (сдвиг растра ~1 px при масштабировании обрезки) и 1 ничья.

## Ограничения
- Шрифты не вшиваются (без шрифта гайда у получателя переносы могут съехать).
- Таблица — фигурами и текстбоксами, не родной таблицей pptx.
- Гиперссылки и `tabular-nums` не переносятся.
- Растр (графики, баннеры) не редактируется.
- Калибровка ширины — по PowerPoint для Mac. В Keynote переносы близкие, но не гарантированы.
- `z-index` не учитывается: порядок объектов — порядок DOM (в гайде z-index нет).

## Прототип
Ранний прототип на python-pptx + Playwright (в репозиторий не входит) — источник правил перевода. Его pptx демо — эталон «не хуже» (см. выше).
